
Q: 它会隔一会儿点一下会话列表,把打开过的会话关掉？
A: 这是**误 toggle** —— 微信里点击"已打开"的会话会把它关闭。
   根因是判断"会话是否已打开"不可靠:
     会话框空白时,第 0 行**仍然是绿色**(那标记的是"最近聊天",
     不是"正在打开"),旧逻辑据此以为已打开,判断就错乱了。
   现已改用**硬判据**:截标题栏算灰度极差 ——
     有会话 = 225(有文字),空白 = 0(纯色)。
   打开状态下连点多次也不会改变会话,已实测验证。

Q: 会话框变成空白了(没选中任何会话),怎么办？
A: 不用手动处理,程序会自动恢复:检测到空白就逐行探测,
   找到目标会话并点开。也可手动在微信里点一下任意会话。

本项目要跑起来，需要四个前置条件全部就绪：

第 1 步配置 API
--------------------------------------------------------------------------------
  位置：WeChatBot_WXAUTO_SE-3.28\config.py

  必填：
    DEEPSEEK_API_KEY   = '你的Key'          （主对话模型）
    DEEPSEEK_BASE_URL  = '服务商地址'
    MODEL              = '模型名'

  推荐用配置面板：
    双击 02_工具面板\VoiceBot控制面板.pyw → ④ 配置面板 → AI 模型
    选服务商（自动填地址）→ 填 Key → 点「测试连通」验证 → 保存

  ✅ 验证标准：控制面板 → ① 环境自检，看到
     "✓ AI 自检通过(使用 xxx): 正常"

第 2 步配置会话
--------------------------------------------------------------------------------
  CHATS 的 key 可以写三种东西，程序会自动解析成真正的 wxid：

      · wxid_xxx      最稳（永不变），但普通用户看不到，要读数据库才有
      · 微信号         好友资料页直接可见，推荐用这个
      · 昵称 / 备注     最直观，但对方改名字后就失效

  ⚠️ 为什么需要解析：
      微信数据库里消息是按 wxid 存的（如 wxid_xxxxxxxxxxxxxxxx）。
      如果直接用微信号当 key 去查，会查不到任何消息（实测 0 条），
      于是机器人就像"聋了"一样永不回复。
      程序内部会先把 key 解析成 wxid 再查库。

  查看有哪些会话 / 拿到 wxid：
    python voice_bot.py --list
      （只需微信登录着，不需要窗口/TTS/AI）

  ⚠️⚠️ 【重要】--list 显示的序号不是界面行号！
      --list 的顺序来自数据库（按"最后消息时间"排），
      而微信界面的顺序是「置顶 + 时间」—— 两者不一致。
      例：--list 里 filehelper 排第 0，但界面上它可能在第 2 行。

  怎么确定界面行号（row）：
      1) 把目标会话在微信里【置顶】
         -> 置顶后它就在列表最前，两个目标就占第 0、1 行，顺序稳定
      2) 看界面上它在第几行（从上往下数，第 1 行 = 0）
      3) --list 现在会顺带打印"当前微信打开的是哪个会话"，
         拿它在界面上的位置来校准

  ✅ 安全兜底：即使 row 填错了，程序自带【会话标题校验】
     —— 点开后用 OCR 读标题，与配置的 name 不符就中止发送，
        绝不会把语音条发给错误的人。
     （早期版本这里会"保守继续"，已修正为严格模式）

  再用 Web UI 可视化配置：
    双击 02_工具面板\VoiceBot控制面板.pyw → ⑦ 角色配置 Web UI
    浏览器打开 http://127.0.0.1:5100
    → 点「从微信导入会话」自动列出所有会话
    → 为要回复的会话填写：行号 row、启用开关
    → 名字务必与实际微信昵称一致（标题校验要用它比对）

  ✅ 验证标准：控制面板 → ① 自检通过；用 ③ 演练模式确认能读到消息

第 3 步写好角色设定（persona）
--------------------------------------------------------------------------------
  在 Web UI 里编辑「角色设定 persona」——这是实际发给 AI 的系统提示词，
  决定 AI 是谁、什么性格、怎么说话。

  示例：
    你是一个名叫小玲的猫娘助手，性格活泼可爱。
    回答要简短口语化，不超过50字。

  也可从 prompts/ 里选现成的（崔琪 / 楚涵 / 爱丽希雅 / 猫娘小玲），
  选「关联 prompt 文件」后确认即可载入。

  ⚠️ persona 写太长会费 token（每条消息都发）；
     且回复过长会被截断（MAX_REPLY_CHARS = 60）。
     语音条不适合长文本，务必在 persona 里要求简短。

第 4 步训练/配置好 TTS 模型
--------------------------------------------------------------------------------
  ① 确认有训练好的权重（GPT 权重 + SoVITS 权重配对使用）

  ② 用配置面板写入：
     ④ 配置面板 → TTS 音色
       选 GPT 权重 + SoVITS 权重 + version（当前 v2Pro）
       点「保存并热切换(免重启)」
       点「试听一句」验证音色

  ③ 配置【参考音频】(极重要,漏了音色会明显失真)
     GPT-SoVITS 靠「参考音频 + 该音频的文字内容」克隆音色。

     把参考音频丢进  VoiceBot\参考音频\  目录(文件名写成语音内容),
     然后执行:
       cd 02_工具面板
       python set_reference.py <音频文件名> --from-name

     查看/切换:
       python set_reference.py            # 查看当前配置
       python set_reference.py --list     # 列出可用参考音频

     ⚠️ 三条硬性要求:
        1. 时长必须在 3~10 秒内(超出会报
           "参考音频在3~10秒范围外，请更换！")
        2. 必须填 prompt_text(即音频里说的话),留空音色会失真
        3. prompt_text 要尽量与音频内容对应,否则音色也会偏

     配置保存在 VoiceBot\reference_config.json,程序会自动读取。

  ④ 启动 TTS 服务：
     控制面板 → ⑥ 启动 TTS 服务
     等待约 20~60 秒，直到日志出现
       "Uvicorn running on http://127.0.0.1:9880"

     ⚠️ 不要关掉那个窗口,关了服务就停。

  ✅ 验证标准：控制面板 → ① 自检，看到 "GPT-SoVITS: 在线"

四步都就绪后，才能正式使用
--------------------------------------------------------------------------------

  控制面板 → ① 环境自检（确认全部通过）
           → ③ 演练模式（不发送，确认回复内容合理）
           → ② 实际发送（真的发语音条）

================================================================================
                   四、⚠️ 注意事项（踩过的坑，务必遵守）
================================================================================

必须保持的状态
--------------------------------------------------------------------------------

  1. 微信窗口必须【最大化】
     所有按钮坐标是按最大化窗口（2584x1540）标定的。
     窗口尺寸一变，比例就失准 → 可能点错位置、录音停不下来。

  2. 默认录音设备 = VoiceMeeter Output
     默认播放设备 = 扬声器  ← 必须是扬声器！
     若播放设备也设成虚拟线卡：你听不到声音，且系统声音会灌进语音条。

  3. 微信必须处于【已登录】状态
     服务器数据库密钥保存在微信进程内存中，
     读取消息需要从内存提取密钥。

  4. 桌面不能锁屏
     发送语音条时需要操作微信窗口（会抢占前台焦点）。

不要做的事
--------------------------------------------------------------------------------

  5. 不要换回 Line 1 (Virtual Audio Cable) 虚拟线卡
     实测该线卡上有一个来源不明的 0.6 秒音频（低沉女声，
     周期性播放，峰值恒为 15958），会混进语音条开头。
     换用 VoiceMeeter 后该问题消失（三种驱动实测零事件）。

  6. 不要手改 tts_infer.yaml 的 version
     服务启动时会把它改写成 v1，与 v2Pro 权重不匹配。
     用配置面板改，它会写对。

  7. 不要把真实联系人放进 CHATS
     只配置你自己的号或愿意接收测试消息的对象。
     发送前脚本会截图存档（05_文档\发送截图），可回查发给了谁。

容易变化的东西
--------------------------------------------------------------------------------

  8. 会话行号 row 会漂移
     微信会话列表按"最后消息时间"排序，聊天一活跃顺序就变。
     建议把要自动回复的对象在微信里【置顶】，行号就固定了。
     发送前脚本会用 OCR 核对会话标题，标题不符会跳过点击。

  9. 音频设备号会变
     改动系统默认音频设备后，sounddevice 的设备索引会整体重排。
     本程序已改为按名称自动查找，但设备名不能变。

 10. 虚拟声卡必须存在
     如果卸载了 VoiceMeeter，需要重新安装并设置：
     播放端 = VoiceMeeter Input，录音端 = VoiceMeeter Output。

性能与维护
--------------------------------------------------------------------------------

 11. 音频文件会自动清理
     默认限额：200 个文件 / 300MB / 7 天，超限自动删最旧的。
     24 小时内生成的文件受保护。每发送 5 条语音自动清理一次。
     可在配置面板 → 音频留存 调整。

 12. 语音条有 60 秒上限
     超过会被微信自动截断。所以 persona 里要限制回复长度。

Q: 语音条开头的空白期有点长？
A: 正常。点录音按钮 → 等录音管线就绪 → 播放音频 → 再点发送，
   中间有约 1.7 秒等待。这段不能省：微信需要时间真正开始取音，
   缩短会直接吃掉字头（第一个字听不清）。
   相关的量在 wx_voice_sender.py 顶部：
     T_REC_SETTLE_AFTER  录音管线就绪等待（不建议改小）
     T_TAIL_COMPACT      播完后的尾巴（默认 0.35 秒）

Q: 语音条发出去了但是静音的？
A: 检查默认录音设备是否为 VoiceMeeter Output。
   运行时日志里会打印"实采信号: RMS=xxx"，
   若 RMS < 50 说明线卡上没有信号。

Q: 录音一直不停（录满 60 秒）？
A: 十有八九是微信窗口没最大化，导致"发送"按钮坐标错位。
   本程序已加入三重录制状态校验，会检测并重试。

Q:【改代码注意】为什么不能"多点一次语音条按钮"来重试？
A: 因为**补点会取消正在进行的录音**。实测数据：
     第1次点击 -> 1.1 秒后 录音态=True（其实已经录上了）
     第2次点击 -> 0.55 秒后 录音态=False（被自己点没了）
   根因是微信的"录音工具栏变绿"有 **1.0~2.3 秒延迟**（时快时慢）：
   旧代码只等 0.8 秒就判定"没进入录音"，于是补点一次，
   结果把刚开始的录音取消掉 —— 表现就是
   "鼠标停在语音条按钮上不动、没有发送点击、也没录上语音"。
   所以现在的规则是：
     · 绝不"等绿色出现再播放"（等它 = 往语音条开头塞静音）；
     · 先固定等 T_REC_SETTLE_AFTER 就播放，播放后再校验；
     · 只有**确认不在录音态**时才允许补点重试。

Q:【重要】语音"录"了，但发送键压根没被点到 / 鼠标停在语音条按钮上不动？
A: 这是**微信窗口被别的窗口盖住**导致的，也是本项目最容易踩的坑。
   原因：
     本程序的点击是"屏幕绝对坐标 + SendInput"，只有当该坐标**真的
     属于微信窗口**时点击才有效。如果微信上面盖着浏览器 / 控制面板 /
     任何窗口，点击会落到**盖在上面的那个程序**上 —— 于是表现为：
       · 微信里看起来"录了音"（因为录音已经启动了）
       · 但"发送"键一次都没被点到，鼠标停在原地不动
       · 更糟的是，还可能误触发别的程序
   已修复（三层防护）：
     1. 每次点击前用 WindowFromPoint 校验该坐标是否属于微信，
        不属于就先把微信提到前台再试；
     2. 3 次仍不行就**直接拒绝点击**并报错，绝不去点别的程序；
     3. 开跑前做整体预检，微信被挡住就提前退出并说明原因。
   你该怎么做：
     · 运行时把微信窗口【最大化】，并点一下微信让它保持在最前面；
     · 不要用别的窗口盖住微信底部工具栏区域（尤其是右下角）；
     · 如果日志里出现"被 xxx 遮挡"，就是这种情况。

Q: 出错了我怎么知道卡在哪一步？
A: 每轮运行都会自动写日志：
     05_文档\运行日志\voicebot_年月日.log
   日志里每一步都有 [1/5]…[5/5] 标记，失败时会打印
     ❌ 发送失败 [卡在: 3-开始录音] 具体原因
   同时 05_文档\发送截图\ 里会保存失败瞬间的截图：
     xxx_fail_blocked.png    微信被别的窗口挡住
     xxx_fail_norecord.png   语音条按钮没点中 / 点击没送到微信
     xxx_fail_play.png       播放到虚拟线缆失败
     xxx_fail_recbroken.png  播放后录音已中断
     xxx_fail_send.png       发送键点了 3 次都没成功
     xxx_recording_start.png 刚进入录音时的工具栏（正常时也有）
   出问题把日志最后 30 行发出来即可定位。

Q: 语音条显示的秒数比实际说的话长？
A: 正常。微信的录音从"点语音条按钮"开始，到"点发送"结束，
   中间包含本程序等待录音管线就绪、校验状态、点发送的耗时，
   这些都会录成首尾静音。例如 6 秒的话显示约 9 秒。
   程序默认走【紧凑模式】把这段压到最小（约 2.4 秒）；
   加 --debug 会打开完整诊断截图，静音会明显变长。

Q: 想抓线缆上到底有没有声音 / 排查音质问题？
A: 用诊断模式：
     python voice_bot.py --live --debug
   它会：① 每一步都存截图；② 播放时同步采集线缆存 *_cable.wav。
   ⚠️ 但**诊断录音不要常开** —— 它会占用微信正在用的录音端点，
      实测会让微信录音中断（表现为"播放后录音已中断"）。
      所以它和 --debug 是独立开关，默认关闭。

Q: 提示"进入录音失败"或"播放后仍未录上"？
A: 说明语音条按钮那一下没生效。程序会先取消、再安全重试一次
   （只有确认不在录音态时才补点，不会把正在进行的录音点没）。
   仍然失败就检查：
     1) 微信窗口是否最大化、是否在最前面（不要被别的窗口挡住）
     2) 日志里 05_文档\发送截图\xxx_retry_norecord.png 当时的画面
     3) 语音条按钮坐标是否还准（窗口尺寸变了要重新采集：
        启动.cmd → [C] 采集按钮坐标）

Q: 怎么重新标定按钮坐标（换了分辨率 / 改了 DPI）？
A: 启动.cmd → [C] 采集按钮坐标。会弹出一个置顶小窗，鼠标移到哪就实时显示：
     坐标 / 所在窗口 / 窗口类名 / 距窗口边缘右·下 / 是否微信
   热键（全局生效，不用切窗口）：
     F8  = 记录当前鼠标位置到"待记录"那一项
     F9  = 保存并退出（写入 01_核心模块\voice_button_coords.json）
     F10 = 退出不保存
   采集顺序：
     ① 语音条按钮（这一步不用录音）
     ② 点微信的语音条按钮开始录音
     ③ 记录「录音中 ⬆ 发送」和「录音中 ✕ 取消」
     ④ 点窗口里的「结束录音」把录音取消掉，别留下空白语音
   注意：记录前确认窗口里「是否微信」显示 ✓，否则记下的是别的程序的坐标。

Q: 提示"未找到微信窗口"？
A: 微信没登录，或窗口被最小化了。恢复窗口并确保已登录。

Q: 提示"AI 配置不完整: key=False"？
A: config.py 里的 DEEPSEEK_API_KEY 是空的，需要填入。

Q: 报"所有模型均不可用"？
A: 最可能是模型名与服务商格式不匹配。各家的模型名规则不同：
     OpenRouter   ->  deepseek/deepseek-v4-pro   (带厂商前缀)
     DeepSeek官方  ->  deepseek-v4-pro            (不带前缀)
     硅基流动      ->  deepseek-ai/DeepSeek-V3
   混合使用会报 "The supported API model names are ..."。
   用配置面板 → AI 模型 →「测试连通」，它会列出该服务商
   真实支持的模型名。

Q: 音色听起来不对劲 / 不像目标角色？
A: 检查两项（都是实测踩过的坑）：
     1. 参考音频的 prompt_text 是否为空 —— 空了音色必失真
     2. 参考音频时长是否在 3~10 秒内 —— 超出会直接报错
   用 02_工具面板\set_reference.py 重新配置。

Q: 报"参考音频在3~10秒范围外，请更换！"？
A: 参考音频超长或过短。用 set_reference.py 换一个 3~10 秒的片段。

Q: TTS 服务启动报 version 相关错误？
A: 用配置面板把 version 改成 v2Pro 再重启服务。

Q: 想把语音发给群聊？
A: 群聊的读取应该可行，但发送语音条到群聊未经验证，
   需要自己测试。
