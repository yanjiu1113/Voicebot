1. 仅供个人学习与自动化技术研究使用。

2. 违反微信用户协议的风险
   本项目通过自动化手段操作微信（模拟鼠标点击 + 读取本地数据库），
   这不符合微信官方用户协议。腾讯有权对账号采取限制措施，
   包括但不限于：强制下线、功能限制、风控验证、乃至封禁。

   实测经验：使用模拟器登录微信曾触发风控（要求完成安全教育）；
             桌面端相对稳定，但风险不为零。

3. 建议措施
   · 先用小号测试，确认稳定后再考虑主力号
   · 保持低频使用，不要批量群发
   · 只在你自己有权控制的账号上使用
   · 不要用于营销、骚扰、群控、加陌生人等行为

4. API Key 安全
   配置文件中包含明文 API Key。分享本项目前务必删除 config.py，
   或改用 config.example.py。一旦 Key 泄露，请立即到服务商后台吊销。

5. 第三方依赖
   本项目依赖多个开源库及第三方服务（见第二节）。
   这些库与服务的可用性、兼容性、许可证由各自作者负责，
   本项目不对其变更导致的失效承担责任。

================================================================================
                  三、✅ 使用顺序（必须按此顺序，缺一不可）
================================================================================

本项目要跑起来，需要四个前置条件全部就绪：

  ① API 配置  →  ② 会话配置  →  ③ 角色设定  →  ④ TTS 模型

第 1 步配置 API
--------------------------------------------------------------------------------
  位置：WeChatBot_WXAUTO_SE-3.28\config.py

  必填：
    DEEPSEEK_API_KEY   = '你的Key'          （主对话模型）
    DEEPSEEK_BASE_URL  = '服务商地址'
    MODEL              = '模型名'

  推荐用配置面板：
    双击 02_工具面板\VoiceBot控制面板.pyw → ④ 配置面板 → AI 模型
    选服务商（自动填地址）→ 填 Key → 点「测试连通」验证 → 保存

  ✅ 验证标准：控制面板 → ① 环境自检，看到
     "✓ AI 自检通过(使用 xxx): 正常"

第 2 步配置会话
--------------------------------------------------------------------------------
  CHATS 的 key 可以写三种东西，程序会自动解析成真正的 wxid：

      · wxid_xxx      最稳（永不变），但普通用户看不到，要读数据库才有
      · 微信号         好友资料页直接可见，推荐用这个
      · 昵称 / 备注     最直观，但对方改名字后就失效

  ⚠️ 为什么需要解析：
      微信数据库里消息是按 wxid 存的（如 wxid_xxxxxxxxxxxxxxxx）。
      如果直接用微信号当 key 去查，会查不到任何消息（实测 0 条），
      于是机器人就像"聋了"一样永不回复。
      程序内部会先把 key 解析成 wxid 再查库。

  查看有哪些会话 / 拿到 wxid：
    python voice_bot.py --list
      （只需微信登录着，不需要窗口/TTS/AI）

  ⚠️⚠️ 【重要】--list 显示的序号不是界面行号！
      --list 的顺序来自数据库（按"最后消息时间"排），
      而微信界面的顺序是「置顶 + 时间」—— 两者不一致。
      例：--list 里 filehelper 排第 0，但界面上它可能在第 2 行。

  怎么确定界面行号（row）：
      1) 把目标会话在微信里【置顶】
         -> 置顶后它就在列表最前，两个目标就占第 0、1 行，顺序稳定
      2) 看界面上它在第几行（从上往下数，第 1 行 = 0）
      3) --list 现在会顺带打印"当前微信打开的是哪个会话"，
         拿它在界面上的位置来校准

  ✅ 安全兜底：即使 row 填错了，程序自带【会话标题校验】
     —— 点开后用 OCR 读标题，与配置的 name 不符就中止发送，
        绝不会把语音条发给错误的人。
     （早期版本这里会"保守继续"，已修正为严格模式）

  再用 Web UI 可视化配置：
    双击 02_工具面板\VoiceBot控制面板.pyw → ⑦ 角色配置 Web UI
    浏览器打开 http://127.0.0.1:5100
    → 点「从微信导入会话」自动列出所有会话
    → 为要回复的会话填写：行号 row、启用开关
    → 名字务必与实际微信昵称一致（标题校验要用它比对）

  ✅ 验证标准：控制面板 → ① 自检通过；用 ③ 演练模式确认能读到消息

第 3 步写好角色设定（persona）
--------------------------------------------------------------------------------
  在 Web UI 里编辑「角色设定 persona」——这是实际发给 AI 的系统提示词，
  决定 AI 是谁、什么性格、怎么说话。

  示例：
    你是一个名叫小玲的猫娘助手，性格活泼可爱。
    回答要简短口语化，不超过50字。

  也可从 prompts/ 里选现成的（崔琪 / 楚涵 / 爱丽希雅 / 猫娘小玲），
  选「关联 prompt 文件」后确认即可载入。

  ⚠️ persona 写太长会费 token（每条消息都发）；
     且回复过长会被截断（MAX_REPLY_CHARS = 60）。
     语音条不适合长文本，务必在 persona 里要求简短。

第 4 步训练/配置好 TTS 模型
--------------------------------------------------------------------------------
  ① 确认有训练好的权重（GPT 权重 + SoVITS 权重配对使用）

  ② 用配置面板写入：
     ④ 配置面板 → TTS 音色
       选 GPT 权重 + SoVITS 权重 + version（当前 v2Pro）
       点「保存并热切换(免重启)」
       点「试听一句」验证音色

  ③ 配置【参考音频】(极重要,漏了音色会明显失真)
     GPT-SoVITS 靠「参考音频 + 该音频的文字内容」克隆音色。

     把参考音频丢进  VoiceBot\参考音频\  目录(文件名写成语音内容),
     然后执行:
       cd 02_工具面板
       python set_reference.py <音频文件名> --from-name

     查看/切换:
       python set_reference.py            # 查看当前配置
       python set_reference.py --list     # 列出可用参考音频

     ⚠️ 三条硬性要求:
        1. 时长必须在 3~10 秒内(超出会报
           "参考音频在3~10秒范围外，请更换！")
        2. 必须填 prompt_text(即音频里说的话),留空音色会失真
        3. prompt_text 要尽量与音频内容对应,否则音色也会偏

     配置保存在 VoiceBot\reference_config.json,程序会自动读取。

  ④ 启动 TTS 服务：
     控制面板 → ⑥ 启动 TTS 服务
     等待约 20~60 秒，直到日志出现
       "Uvicorn running on http://127.0.0.1:9880"

     ⚠️ 不要关掉那个窗口,关了服务就停。

  ✅ 验证标准：控制面板 → ① 自检，看到 "GPT-SoVITS: 在线"

四步都就绪后，才能正式使用
--------------------------------------------------------------------------------

  控制面板 → ① 环境自检（确认全部通过）
           → ③ 演练模式（不发送，确认回复内容合理）
           → ② 实际发送（真的发语音条）

================================================================================
                   四、⚠️ 注意事项（踩过的坑，务必遵守）
================================================================================

必须保持的状态
--------------------------------------------------------------------------------

  1. 微信窗口必须【最大化】
     所有按钮坐标是按最大化窗口（2584x1540）标定的。
     窗口尺寸一变，比例就失准 → 可能点错位置、录音停不下来。

  2. 默认录音设备 = VoiceMeeter Output
     默认播放设备 = 扬声器  ← 必须是扬声器！
     若播放设备也设成虚拟线卡：你听不到声音，且系统声音会灌进语音条。

  3. 微信必须处于【已登录】状态
     服务器数据库密钥保存在微信进程内存中，
     读取消息需要从内存提取密钥。

  4. 桌面不能锁屏
     发送语音条时需要操作微信窗口（会抢占前台焦点）。

不要做的事
--------------------------------------------------------------------------------

  5. 不要换回 Line 1 (Virtual Audio Cable) 虚拟线卡
     实测该线卡上有一个来源不明的 0.6 秒音频（低沉女声，
     周期性播放，峰值恒为 15958），会混进语音条开头。
     换用 VoiceMeeter 后该问题消失（三种驱动实测零事件）。

  6. 不要手改 tts_infer.yaml 的 version
     服务启动时会把它改写成 v1，与 v2Pro 权重不匹配。
     用配置面板改，它会写对。

  7. 不要把真实联系人放进 CHATS
     只配置你自己的号或愿意接收测试消息的对象。
     发送前脚本会截图存档（05_文档\发送截图），可回查发给了谁。

容易变化的东西
--------------------------------------------------------------------------------

  8. 会话行号 row 会漂移
     微信会话列表按"最后消息时间"排序，聊天一活跃顺序就变。
     建议把要自动回复的对象在微信里【置顶】，行号就固定了。
     发送前脚本会用 OCR 核对会话标题，标题不符会跳过点击。

  9. 音频设备号会变
     改动系统默认音频设备后，sounddevice 的设备索引会整体重排。
     本程序已改为按名称自动查找，但设备名不能变。

 10. 虚拟声卡必须存在
     如果卸载了 VoiceMeeter，需要重新安装并设置：
     播放端 = VoiceMeeter Input，录音端 = VoiceMeeter Output。

性能与维护
--------------------------------------------------------------------------------

 11. 音频文件会自动清理
     默认限额：200 个文件 / 300MB / 7 天，超限自动删最旧的。
     24 小时内生成的文件受保护。每发送 5 条语音自动清理一次。
     可在配置面板 → 音频留存 调整。

 12. 语音条有 60 秒上限
     超过会被微信自动截断。所以 persona 里要限制回复长度。

                                 六、常见问题
================================================================================

Q: 语音条开头的空白期有点长？
A: 正常。点录音按钮 → 等待录音启动 → 播放音频 → 再点发送，
   中间有约 1.8 秒等待。可调整 wx_voice_sender.py 里的
   T_RECORD_SETTLE / T_TAIL，但缩短会增加点击失败风险。

Q: 语音条发出去了但是静音的？
A: 检查默认录音设备是否为 VoiceMeeter Output。
   运行时日志里会打印"实采信号: RMS=xxx"，
   若 RMS < 50 说明线卡上没有信号。

Q: 录音一直不停（录满 60 秒）？
A: 十有八九是微信窗口没最大化，导致"发送"按钮坐标错位。
   本程序已加入三重录制状态校验，会检测并重试。

Q: 提示"未找到微信窗口"？
A: 微信没登录，或窗口被最小化了。恢复窗口并确保已登录。

Q: 提示"AI 配置不完整: key=False"？
A: config.py 里的 DEEPSEEK_API_KEY 是空的，需要填入。

Q: 报"所有模型均不可用"？
A: 最可能是模型名与服务商格式不匹配。各家的模型名规则不同：
     OpenRouter   ->  deepseek/deepseek-v4-pro   (带厂商前缀)
     DeepSeek官方  ->  deepseek-v4-pro            (不带前缀)
     硅基流动      ->  deepseek-ai/DeepSeek-V3
   混合使用会报 "The supported API model names are ..."。
   用配置面板 → AI 模型 →「测试连通」，它会列出该服务商
   真实支持的模型名。

Q: 音色听起来不对劲 / 不像目标角色？
A: 检查两项（都是实测踩过的坑）：
     1. 参考音频的 prompt_text 是否为空 —— 空了音色必失真
     2. 参考音频时长是否在 3~10 秒内 —— 超出会直接报错
   用 02_工具面板\set_reference.py 重新配置。

Q: 报"参考音频在3~10秒范围外，请更换！"？
A: 参考音频超长或过短。用 set_reference.py 换一个 3~10 秒的片段。

Q: TTS 服务启动报 version 相关错误？
A: 用配置面板把 version 改成 v2Pro 再重启服务。

Q: 想把语音发给群聊？
A: 群聊的读取应该可行，但发送语音条到群聊未经验证，
   需要自己测试。
