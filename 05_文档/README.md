# VoiceBot —— 微信语音自动回复

让 AI 角色用 **GPT-SoVITS 克隆音色**在微信发出**真正的语音条**(语音条,不是音频文件)。

> 全程使用微信官方语音条通道 —— **无 Hook、无协议逆向、无进程内存改写**。

**版本:1.0.0**(见 `VERSION` / `CHANGELOG.md`)

## 二、工作原理

```
微信收到消息
   └─> 解密本地数据库读取(replica,不依赖 UIA)
        └─> AI 生成回复(DeepSeek / OpenRouter / 硅基流动 …)
             └─> GPT-SoVITS 合成 WAV
                  └─> 播到虚拟声卡(VoiceMeeter Input)
                       └─> 微信默认麦克风 = 该声卡输出端 → "听到"音频
                            └─> 鼠标模拟:点语音条按钮 → 播放 → 点发送
                                 └─> 真·微信语音条发出
```

**为什么必须这样**:微信 4.1.x 聊天区**自绘渲染**(类名前缀
`MMUIRenderSubWindow`),对 UIAutomation 完全不暴露可用的聊天控件,
所以 wxauto / pyweixin 等基于 UIA 的方案**架构性不可用**。

## 三、必须满足的前提(缺一不可)

| 项 | 要求 |
|---|---|
| 微信 | 桌面版**已登录**,窗口**最大化** |
| 窗口层级 | 微信要**在最前面**,不能被别的窗口盖住(见下方警告) |
| 默认**录音**设备 | `VoiceMeeter Output (VB-Audio VoiceMeeter VAIO)` |
| 默认**播放**设备 | **扬声器**(必须!否则听不到声音且系统声会灌进去) |
| TTS 服务 | `api_v2.py` 运行在 `127.0.0.1:9880` |
| 桌面 | 未锁屏;发送时会**抢占前台焦点** |

> ⚠️ **窗口必须最大化** —— 所有坐标按最大化标定。窗口尺寸一变,比例就失准。

> ⚠️ **别让任何窗口盖住微信**。点击用的是"屏幕绝对坐标",
> 被盖住时会点到**盖在上面的那个程序**上(程序已加校验会拦下并报错,
> 但那次发送就失败了)。尤其注意右下角工具栏区域不要被遮挡。

## 五、配置说明

### 🔑 首次使用:填入 API Key(必做)

**位置:`WeChatBot_WXAUTO_SE-3.28\config.py`**

仓库里发布的是 `config.example.py`(**所有 Key 都是 `YOUR_API_KEY_HERE`**)。
直接复制一份改名即可:

```powershell
cd WeChatBot_WXAUTO_SE-3.28
Copy-Item config.example.py config.py
```

然后填这几个值:

| 配置项 | 说明 | 模板值 |
|---|---|---|
| `DEEPSEEK_API_KEY` | **主对话模型,必填** | `YOUR_API_KEY_HERE` |
| `DEEPSEEK_BASE_URL` | 服务商地址 | `https://api.deepseek.com` |
| `MODEL` | 模型名(**出现两次,两处都要改**) | `deepseek-v4-pro` |
| `MOONSHOT_API_KEY` | 图片/表情识别,可选 | 空 |
| `ONLINE_API_KEY` | 联网搜索,可选 | 空 |
| `MAX_TOKEN` | 输出上限 | 2000 |

> ⚠️ **`MODEL` 在文件里出现两次**(一处是旧配置残留),手动改时两处都要改。
> 配置面板会自动同步改所有出现的位置。

**填法(两种任选):**

1. **配置面板**(推荐):`启动.cmd` → [3] 配置面板
   → 「AI 模型」标签页 → 选服务商 → 填 Key → 点「测试连通」验证 → 保存
2. **手动改**:编辑 `config.py`,把 `DEEPSEEK_API_KEY = ''`
   改成 `DEEPSEEK_API_KEY = '你的Key'`

`config.py` 已被 `.gitignore` 忽略,**不会进仓库**。

常见服务商地址:

| 服务商 | BASE_URL |
|---|---|
| DeepSeek 官方 | `https://api.deepseek.com` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| 硅基流动 | `https://api.siliconflow.cn/v1` |
| 月之暗面 | `https://api.moonshot.cn/v1` |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` |

> ⚠️ **模型名必须和当前服务商匹配** —— 这是最容易踩的坑:
> ```
> OpenRouter   ->  deepseek/deepseek-v4-pro    (带厂商前缀)
> DeepSeek官方  ->  deepseek-v4-pro             (不带前缀)
> 硅基流动      ->  deepseek-ai/DeepSeek-V3
> ```
> 混用会报 `The supported API model names are ...`。
> 用配置面板的「测试连通」可以列出该服务商**真实支持**的模型名。
> 即使配错,`voice_bot.py` 也会**自动回退**到可用模型。

### TTS 音色(GPT + SoVITS 两个模型)

**位置:`GPT-SoVITS-v2pro-20250604-nvidia50\GPT_SoVITS\configs\tts_infer.yaml`**

```yaml
custom:
  t2s_weights_path:  .../GPT_weights_v2Pro/Elysia_v2-e15.ckpt      ← GPT 权重
  vits_weights_path: .../SoVITS_weights_v2Pro/Elysia_v2_e24_s13080.pth  ← SoVITS 权重
  version: v2Pro                                                    ← 训练版本
```

配置面板会写入此文件,并在 TTS 服务**在线时热切换(免重启)**。

可用的权重(实测):

| 角色 | GPT 权重 | SoVITS 权重 |
|---|---|---|
| 爱莉希雅 | `Elysia_v2-e15.ckpt` | `Elysia_v2_e24_s13080.pth` |
| zekai | `zekai-e15.ckpt` | `zekai_e4_s104.pth` |
| yayi | `yayi_custom_voice-e15.ckpt` | `yayi_custom_voice_e8_s200.pth` |

**⚠️ `version` 必须与权重训练版本一致** —— 当前全是 **v2Pro**。
(实测:服务启动时会把 `version` 改写成 `v1`,需注意核对)

### 🎤 参考音频(决定音色像不像,有三条硬性要求)

**位置:`VoiceBot\reference_config.json`** —— 用
`02_工具面板\set_reference.py` 配置,或在配置面板「TTS 音色」标签页选。

| 要求 | 说明 |
|---|---|
| 1. 时长 **3~10 秒** | 超出会直接报"参考音频在3~10秒范围外,请更换!" |
| 2. **必须填 `prompt_text`** | 即这段音频对应的文字。**留空音色必然失真** |
| 3. `prompt_text` 要和音频**内容一致** | 对不上也会影响还原度 |

配置面板会校验时长并拦截不合规的文件。

### 音频留存(配置面板 ⑤)

三重限额,任一超出即从最旧的删:

| 项 | 默认 |
|---|---|
| `max_files` | 200 个 |
| `max_total_mb` | 300 MB |
| `max_age_days` | 7 天 |
| `min_age_hours` | 24(保护期,此时间内绝不删) |

### 自动回复对象

**位置:`01_核心模块\voice_bot.py`** 的 `CHATS`
(首次运行会从 `voice_bot.example.py` 自动生成这个文件)

```python
CHATS = {
    # key 可以是 wxid / 微信号 / 昵称,程序会自动解析
    "请填对方的微信号或昵称": {
        "name": "会话列表里显示的昵称",   # 用于 OCR 核对,防发错人
        "row": 0,                          # 界面列表行号(0 起)
        "enabled": True,                   # False = 临时停用这个角色
        "persona": "在这里写角色设定……",
    },
}
```

推荐直接用 **控制面板 ⑦ 角色配置 Web UI**(浏览器里可视化编辑,
还能一键从微信导入会话列表)。

> ⚠️ **`row` 是"会话在微信界面列表里的行号",不是 `--list` 的序号!**
> `--list` 的顺序来自**数据库**(按最后消息时间),而界面顺序是
> **置顶 + 时间**,两者**不一致**,所以 `--list` 的序号**不能直接当 row 用**。
> 行号还会随时间漂移 —— **强烈建议把要自动回复的会话在微信里置顶**。
> 即使填错也**不会发错人**:发送前会 OCR 核对标题,不符就中止本次发送。

## 六、排错

### 先看这两个地方

| 位置 | 内容 |
|---|---|
| `05_文档\运行日志\voicebot_年月日.log` | 每轮运行日志,每步都有 `[1/5]`…`[5/5]` 标记 |
| `05_文档\发送截图\` | 每次发送的截图;失败会存 `xxx_fail_*.png` |

失败时日志里会直接打印卡在哪一步,例如:

```
❌ 发送失败 [卡在: 3-开始录音] 具体原因
```

失败截图命名对照:

| 文件名 | 含义 |
|---|---|
| `_fail_blocked.png` | 微信被别的窗口挡住,拒绝点击 |
| `_fail_norecord.png` | 语音条按钮没点中 / 点击没送到微信 |
| `_fail_play.png` | 播放到虚拟线卡失败 |
| `_fail_recbroken.png` | 播放后仍未录上(已安全重试过一次) |
| `_fail_send.png` | 发送键点了 3 次都没成功 |
| `_recording_start.png` | 刚进入录音时的工具栏(仅 `--debug`) |

### 命令行参数

```powershell
python 01_核心模块\voice_bot.py --check    # 只做环境自检
python 01_核心模块\voice_bot.py            # 演练模式(不发送)
python 01_核心模块\voice_bot.py --live     # 实际发送
python 01_核心模块\voice_bot.py --list     # 列出会话与数据库序号
python 01_核心模块\voice_bot.py --once     # 只跑一轮就退出
python 01_核心模块\voice_bot.py --reset    # 清空消息水位
python 01_核心模块\voice_bot.py --live --debug   # 诊断模式
```

**`--debug`** 会:每步存截图 + 播放时同步采集线缆存 `*_cable.wav`。
排查问题时用;**平时不用**,因为它会明显拉长语音条首尾的静音。

> ⚠️ 诊断**录音**是独立开关(`DIAG_RECORD`,默认关),**不会**被 `--debug`
> 打开 —— 因为它会打开微信正在用的录音端点,实测会导致发出**空语音条**。

### 常见问题

| 现象 | 根因 | 处理 |
|---|---|---|
| **UIA 方案全废** | 微信 4.1.x 聊天区自绘渲染 | 改走「数据库读取 + 坐标模拟」 |
| 微信 4.1.12 / 4.1.2 **无法登录** | 服务端拒绝"版本过低" | 当前用 **4.1.9.57** |
| **Line 1 线卡有神秘音频** | 来源不明:0.6 秒低沉女声,周期性播放,峰值恒 15958,会混进语音条 | **改用 VoiceMeeter**(实测三种驱动全零事件) |
| **微信被别的窗口盖住** | 点击是屏幕绝对坐标,会落到**盖在上面的程序**上:微信里"录了音"但发送键没被点到,鼠标停着不动 | 每次点击前用 `WindowFromPoint` 校验归属,不属于微信就抢回前台;仍不行则**拒绝点击**并报错 |
| **重试时补点语音条按钮** | 会把**正在进行的录音直接取消**(绿色工具栏有 1~3 秒延迟,容易误判"没录上") | 改为"先固定等待 → 播放 → 播放后校验",且**只在确认不在录音态时**才补点 |
| 语音条首尾静音长 | 微信从"点按钮"就开始录,程序中间的等待全被录进去 | 默认紧凑模式;加 `--debug` 会更长 |
| 发出**空语音条** | 诊断录音抢占微信录音端点 / TTS 返回静音 | 默认关诊断录音;发送前校验音频峰值,过低拒发 |
| 会话被误关 | 微信会话已打开时再点会 **toggle 关闭** | `session_guard` OCR 读标题,已打开则跳过点击 |
| 点击不生效 | Windows **前台锁定** | `AttachThreadInput` 附加到前台线程 |
| 设备号突然失效 | 改默认设备后 **sounddevice 索引整体重排** | 改为**按名称自动查找** |
| WASAPI 录音端报错 | 探测能过、实开却报 `Invalid sample rate` | 录音改用 **DirectSound** |
| `tasklist` 返回空 | 环境限制 | 用 `psutil` 替代 PID 检测 |
| 报"所有模型均不可用" | 模型名与服务商格式不匹配 | 见「五、配置说明」的服务商前缀说明 |
| `tts_infer.yaml` 的 `version` 被改回 `v1` | 服务启动时改写 | 用配置面板改,它会写对 |
| 报"参考音频在3~10秒范围外" | 参考音频超长或过短 | 换一段 3~10 秒的,用 `set_reference.py` |

## 七、坐标标定(如需重新标定)

基准:微信窗口最大化,`MEASURED_WINDOW = {x: -12, y: -12, w: 2584, h: 1540}`
(实测采集于 2026-09-19,屏幕 2560x1600)

| 控件 | 绝对坐标 | 距右 | 距下 |
|---|---|---|---|
| 语音条按钮(圆形声波图标) | **(2347, 1450)** | 225 | 78 |
| 录音中 ⬆ 发送(绿色圆形) | **(2483, 1443)** | 89 | 85 |
| 录音中 ✕ 取消(灰色圆形) | **(2129, 1444)** | 443 | 84 |

> 窗口右边缘 = `-12 + 2584 = 2572`,下边缘 = `-12 + 1540 = 1528`。

坐标取自 `01_核心模块\wx_voice_sender.py` 的 `BUTTONS_MEASURED`;
可用同目录的 `voice_button_coords.json` 覆盖(跑 `02_工具面板\采集按钮坐标.py` 生成)。

**`anchor_pos()` 的实际策略(两级)**:

1. 窗口尺寸与 `MEASURED_WINDOW` 相差 ≤4px → **直接用实测绝对坐标**(最准);
2. 否则按窗口内**相对位置等比换算**。

> ⚠️ 早期版本用的是"距右/下边缘偏移"推算,已**彻底废弃** ——
> 基准窗口尺寸一变就整体偏移(实测偏 12 像素就足以点空)。
> 代码注释里若再看到"边缘偏移兜底"的说法,是过期描述。

> **语音转文字的麦克风图标 ≠ 语音条按钮!**
> 语音条按钮是**发送键左边那个圆形声波图标**(点它开始录音)。
